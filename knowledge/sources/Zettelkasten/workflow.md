# Zettelkasten 工作流程

PURPOSE: 把 Zettelkasten overview 的概念整理成日常可執行流程，從捕捉材料到形成可寫作的筆記網路。
APPLIES TO: daily note workflow, reading workflow, writing workflow, knowledge production.
關鍵字: capture, reading notes, Zettel, link notes, outline, writing from notes.

> 本文件整理自 Zettelkasten.de overview；非官方譯文。

---

## 0. 捕捉

先把材料放進 inbox 或 buffer note，不要在捕捉階段追求完美。

可捕捉的材料：

- 閱讀摘記。
- 問題與疑惑。
- 自己的判斷或反駁。
- 可用於文章的例子。
- 需要之後查證的來源。

捕捉的目的只是避免流失，不代表它已經進入 note archive。

---

## 1. 解讀來源

Zettelkasten 的關鍵不是保存原文，而是解讀來源。

處理來源時應問：

- 這段材料真正主張什麼？
- 我如何用自己的話重述它？
- 它支持或反駁我 archive 裡哪個既有想法？
- 它能形成新 Zettel，還是只是一個 reference？
- 它與哪些問題、寫作計畫或結構筆記有關？

若只是剪貼原文或保留標註，仍停留在 collector's fallacy。必須經過理解與轉化。

---

## 2. 建立 Zettel

把值得長期保存的想法轉成 Zettel。

一則好的 Zettel 通常具備：

- 單一主題或單一想法。
- 可獨立理解的文字。
- 必要來源或引用。
- 與既有筆記的連結。
- 未來可被寫作、研究或決策重用的表述。

不要把一整篇閱讀筆記直接放進 archive。閱讀筆記應拆成可連結、可重組的想法單元。

---

## 3. 建立連結

建立 Zettel 後，最重要的工作是把它放進知識網。

連結時應補上關係語境：

- 為什麼連到這則筆記？
- 這是例子、延伸、反例、證據，還是結構關係？
- 這條連結未來會如何幫助我重新理解這個問題？

單純塞一堆 backlinks 不一定有用。好的連結應讓未來的自己知道為什麼這兩個想法該一起看。

---

## 4. 使用 tags 與 structure notes

Tags 提供鬆散聚合，structure notes 提供有意義的路徑。

使用 tags：

- 用於跨主題、狀態或用途的聚合。
- 避免太泛、太細或一次性 tag。
- 不要把 tags 當成僵硬目錄。

使用 structure notes：

- 整理某一主題下的重要 Zettel。
- 建立論證順序或寫作路徑。
- 作為未來寫作 outline 的雛形。
- 幫助 archive 在成長後仍可導航。

---

## 5. 從筆記進入寫作

Overview 建議用 outlines 啟動寫作，再把 Zettel 加入 outline 中。

實作方式：

1. 建立寫作題目的 outline。
2. 從 archive 找出相關 Zettel。
3. 把 Zettel 放到 outline 的合適位置。
4. 依照論述順序補橋接文字。
5. 分開 composing 與 editing，先形成草稿，再修整語氣與結構。

這讓寫作不再從空白頁開始，而是從已經累積、連結與解讀過的想法出發。

---

## 6. 持續迭代

Zettelkasten 是長期流程，不是一次整理專案。

日常迭代可以很小：

- 把一則 inbox note 轉成 Zettel。
- 替舊 Zettel 補一條更清楚的連結。
- 建立或更新一則 structure note。
- 把某個 buffer note 拆成數則 atomic notes。
- 把一組 Zettel 放進文章 outline。

重要的是持續工作，而不是累積未處理材料。
