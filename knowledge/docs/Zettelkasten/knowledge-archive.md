# Zettelkasten 知識庫結構

PURPOSE: 整理 Zettelkasten 的基本組件與長期擴展方式，包括 inbox、note archive、reference manager、buffer notes、evidence layers 與 structural layers。
APPLIES TO: note archive design, source management, scaling personal knowledge base, structure notes.
關鍵字: inbox, note archive, reference manager, buffer notes, evidence layers, structural layers, structure notes.

> 本文件是依據 Zettelkasten.de overview 的 Knowledge Management 與 Scaling your note archive 段落整理；非官方譯文。

---

## 三個基本組件

Zettelkasten 的基礎組件有三個：

- **Inbox**：暫時捕捉想法、摘錄、待處理材料與靈感。
- **Note archive**：長期保存已處理、可連結、可重用的 Zettel。
- **Reference manager**：管理來源資料，例如書籍、文章、網址、論文與引用資訊。

這三者不要混為一談：

- Inbox 允許混亂，因為它是暫存。
- Note archive 需要可理解、可連結、可回訪。
- Reference manager 保存來源，不等於保存你的理解。

---

## Inbox：捕捉但不等於完成

Inbox 的作用是降低捕捉成本，讓想法與材料先不要流失。

適合放進 inbox 的內容：

- 閱讀時的摘記。
- 待解讀的來源片段。
- 突然想到的連結或問題。
- 寫作靈感。
- 尚未整理的主題材料。

Inbox 的風險是堆積。若材料一直留在 inbox，就只是收藏，不是知識管理。需要定期把有價值的材料轉成 Zettel、連到既有筆記，或刪除。

---

## Note archive：長期筆記網路

Note archive 是 Zettelkasten 的核心。進入 archive 的筆記應該：

- 用未來的自己也能理解的方式書寫。
- 聚焦於單一想法。
- 有足夠脈絡，不依賴原始來源才能理解。
- 能被其他筆記引用。
- 與相關筆記建立明確連結。

Archive 不只是資料庫，而是想法網路。它應該能在搜尋與瀏覽時帶來意外發現，讓使用者看到以前沒有主動想到的關係。

---

## Reference manager：來源管理

Reference manager 保存來源資訊，讓筆記中的主張、摘錄或閱讀脈絡可追溯。

它可以保存：

- 書籍與文章 metadata。
- URL 與存取資訊。
- 引用格式。
- 原文摘錄位置。
- 閱讀狀態。

但來源管理器不是 Zettelkasten 本身。來源資料必須被解讀，轉成自己的想法，並與 archive 建立連結，才真正進入知識生產流程。

---

## Buffer notes：處理資訊流量

當資訊大量湧入時，可以使用 temporary buffer notes 暫時收集材料，之後再拆分、重排與轉化。

Buffer notes 適合：

- 收集某個寫作題目的材料。
- 暫存同一來源的閱讀摘記。
- 收集一段時間內同一問題的線索。
- 建立初步 outline 前的材料池。

Buffer notes 不應永久取代 Zettel。它們是過渡層，目標是被拆解、連結、整合或淘汰。

## Evidence layers：內容層次

Overview 提到，隨著 archive 成長，筆記會出現不同層次的內容。可概括為三層：

1. **Data description and patterns**：描述資料、觀察現象、記錄模式。
2. **Interpretation**：解讀描述與模式，形成理解或判斷。
3. **Synthesis**：把描述、模式與解讀綜合成更高層次的主張。

這提醒我們：不是所有筆記都處在同一抽象層級。好的 Zettelkasten 允許底層觀察、中層解讀與高層綜合互相連結。

---

## Structural layers：結構層次

當 archive 成長，僅靠單則筆記之間的連結會變得難以導航，需要結構層。

Overview 提到三個層次：

- **Bottom layer: Content**：一般 Zettel，承載具體想法。
- **Middle layer: Structure notes**：整理某個主題或問題下的筆記關係。
- **Top layer: Main structure notes and special tags**：更高層的主題入口、主目錄或特殊標籤。

Structure notes 的價值不是分類，而是建立路徑。它可以像主題地圖、outline 或索引，幫助使用者在一群相關筆記中看見關係與順序。
